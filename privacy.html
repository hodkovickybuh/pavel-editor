Privacy policy

PAVEL EDITOR is a visual editor that runs inside a web page you are already looking at. It has no server, no account and nothing to log in to.

It collects nothing. No analytics, no telemetry, no tracking, no profiles, no cookies of its own. Nothing you edit is sent to us, because there is no us to send it to.

Applies to the PAVEL EDITOR extension on the Chrome Web Store and to the script distributed from this repository · Version 1.10.0 · Last updated 31 July 2026

What the extension can access, and when

The extension declares two permissions and no host permissions:

  • activeTab — access to a single tab, granted by Chrome at the moment you click the toolbar icon, and only for that tab. It cannot read a page you have not clicked the icon on, it has no list of the sites you visit, and it does not run in the background waiting for one.
  • scripting — the ability to inject the editor's script into that tab once the click has granted access.

Chrome shows these to you before you install, and the Web Store listing declares the same two and nothing else. There is a service worker, and it contains exactly one thing: a listener that injects the editor when you click the icon. It observes nothing else.

Once injected, the editor necessarily reads the page in front of you: its elements, styles, text and stylesheets. That is what an editor is. Everything it reads stays in that tab's memory and in that browser's own storage, unless you deliberately export it (see below).

Every network request it makes

Three, all listed. There are no others, and you can verify that by searching the source for fetch.

RequestWhenWhat it carries
data.jsdelivr.com
version check		 Once per session, when the editor is opened Nothing of yours. It asks the public jsDelivr API for the list of released versions so the panel can tell you a newer one exists. Like any HTTP request, jsDelivr will see your IP address, user agent and the time; it is not told which page you are on or anything you edited. If the request fails or is blocked, nothing happens except that you do not get the update banner.
127.0.0.1:7331/ping
bridge detection		 Only on a local page (localhost, 127.0.0.1, *.local), when the editor is opened Nothing. It asks whether you are running the optional local bridge on your own machine. It never leaves your computer, and it is not attempted at all on a public site.
127.0.0.1:7331/report
APPLY TO CODE		 Only when you press the button, and only if you started the bridge yourself The report: the CSS properties you changed, the rules and files they belong to, any text you edited, and any notes you wrote. It goes to a program running on your own machine, which writes it into a folder in your own project. Nothing about it touches the internet.

If you load the editor from the jsDelivr CDN instead of the extension, then, exactly as with any script tag, jsDelivr serves the file and sees the request for it. The extension does not do this: it ships the script inside itself.

What is stored, and where

In your browser only, under the origin of the page you are editing. Nothing is stored by us, and nothing is synced anywhere.

KeyWhereWhat it holds
pavel-editor-v1<path>sessionStorageYour unapplied edits for that page, so a reload or a dev-server rebuild does not lose an hour of work. Cleared when you close the tab.
pe-variant-A, pe-variant-BsessionStorageThe two saved A/B directions. Cleared when you close the tab.
pe-recent-colorslocalStorageThe last eight colours you picked, so the swatch row is useful.
pe-open-groups, pe-panel-poslocalStorageWhich inspector groups you left open and where you dragged the panel.

While the editor is open it also adds one <style> element and a data-pe-id attribute to the elements you have edited, so it can preview your changes without touching the page's own inline styles. Those live in the page's memory and disappear on reload. Clearing your browser storage for a site removes everything above.

Things you export, deliberately

Two, both of which require you to press something:

  • COPY FOR AI writes the report to your clipboard. Where it goes next is entirely your choice: an assistant, a colleague, a note. The editor does not send it anywhere.
  • Save session downloads the change-set as a JSON file to your own machine.

Images you drag onto the page to preview a swap are never uploaded. They are held as a temporary in-memory URL, and the report only names the file so whoever applies it knows which asset to ask you for.

Plainly, then

neverAnalytics, telemetry, crash reporting, session replay, fingerprinting, advertising identifiers, or any third-party SDK. There are no third-party libraries in the shipped bundle beyond React, which makes no network calls.
neverSending your page content, your edits, your keystrokes, your credentials or your browsing history to us or to anyone else.
neverSelling, renting or sharing data. There is none to sell.
neverRunning on a page you have not opened it on.
onlyA version check against a public CDN, a localhost check for the optional bridge, and whatever you export by pressing a button.

Children, and legal bases

The editor is a developer and designer tool, not directed at children, and it does not knowingly process anyone's personal data at all. Since no personal data is collected, there is nothing to request access to, correct, export or erase, and no transfer of data across borders takes place. If you are assessing this under the GDPR, the honest summary is that no processing by us occurs: the software runs locally in your browser.

Verify it yourself

This policy describes a program whose entire source is public and small enough to read. The claims above map to specific lines:

  • Permissions: extension/manifest.json
  • The one thing the service worker does: extension/background.js, nine lines
  • Every network call: search src/ for fetch(, which returns the three above
  • Every storage key: search src/ for sessionStorage and localStorage
  • The bridge, which never writes to your source files: bin/bridge.mjs

If you find anything on this page that the code contradicts, that is a bug in the policy and worth opening an issue about.

Changes, and contact

If this policy changes, the updated date at the top changes with it and the old version stays in the repository's git history, which is a more honest changelog than a paragraph promising to notify you. Questions go to the issue tracker, which is public, so please do not put anything private in one.
