Not in the Chrome Web Store yet

Install the editor in about ninety seconds.

The extension is not published in the Chrome Web Store, so it installs the way developers install extensions: unzip a folder, turn on developer mode, load it. Nothing is compiled, nothing runs in the background, and you can delete it by dragging the folder to the bin.

⬇ Download the zip Watch the narrated walkthrough
⚠
Why developer mode? Publishing to the Web Store needs a paid developer account and a review queue. Until that is done, "Load unpacked" is the official Chrome path for running an extension from a folder. It is the same mechanism every extension developer uses daily.

The install

Five steps, once.

Chrome keeps the extension after this. You only repeat it when a new version ships, and the editor tells you when that happens.

1

Download and unzip

Grab pavel-editor-extension.zip from the latest release. Double-click it. You want the folder that comes out, called extension, and you want to leave it somewhere permanent: your Documents, not Downloads. Chrome loads it from that path every time it starts, so if the folder moves the extension breaks.

Finder · Documents
📁 extension/ — manifest.json · pavel-editor.js · background.js · icons/

Keep the whole folder together. The manifest at its root is what Chrome reads.

2

Open the extensions page

Type chrome://extensions into the address bar and press enter. You cannot get there by clicking a link, Chrome blocks that on purpose, so it has to be typed or pasted.

chrome://extensions
Extensions Developer mode

The developer mode switch sits at the top right of that page.

3

Turn on developer mode

Top right of that page, one switch. Turning it on reveals three buttons on the left: Load unpacked, Pack extension, Update. Nothing else about your browser changes.

chrome://extensions
Load unpacked Pack extension Update Developer mode
4

Load unpacked, and pick the folder

Click Load unpacked and select the extension folder itself, not a file inside it and not the zip. PAVEL EDITOR appears in the list straight away. If Chrome complains about the manifest, you have selected the wrong level: go one folder in or out until you see manifest.json sitting at the top.

chrome://extensions
PAVEL EDITOR
1.9.1 · A Figma-style visual editor for any live page
5

Pin it, then click it on any page

Open the puzzle-piece icon in Chrome's toolbar and pin PAVEL EDITOR so it is always one click away. Then go to any page and click the icon: the panel appears in the top right. Click it again later and a hidden editor comes straight back.

https://any-site-you-are-working-on.com 🧩✎

The ✎ icon is the editor. One click arms it on the tab you are looking at, and nothing runs anywhere else.

✓
What it can and cannot see. The extension asks for activeTab only, which means it gets access to a tab at the moment you click its icon, and to nothing before or after. It has no background page watching you, sends nothing anywhere, and stores your edits in your own browser's session storage. The source is public, and the privacy policy lists every network request and storage key it uses, with the file to check each claim against.

Other ways to run it

Three, and when each one is right.

Best on any site

The extension

Works everywhere, including sites whose Content-Security-Policy blocks injected scripts: github.com, banks, most large products. Extension injection is exempt from the page's CSP, which is exactly why this exists.

Best on your own project

The bridge

In the project folder run the command below, then load the script it prints. The panel's button becomes APPLY TO CODE and every report lands in .pavel-editor/ in that project, where your coding assistant can read it without you pasting anything.

npx pavel-editor-bridge
Quickest, own sites only

The console line

Paste this into DevTools on a page you control. On a strict site it fails with a CSP error, which is the site refusing, not the editor breaking.

var s=document.createElement('script');
s.src='https://cdn.jsdelivr.net/gh/hodkovickybuh/pavel-editor@v1.9.2/dist/pavel-editor.js';
document.body.appendChild(s);

Tutorials

Ten minutes, ten things.

Do these in order on the playground page and you will have used every part of the tool. Each one takes under a minute.

click · drag

1 · Move something

Click the big headline. Drag it. The panel shows what changed, in mint.

Why it matters: you are moving the real element in the real page, not a picture of it, so what you see is what the CSS will do.

drag an edge

2 · Resize a card

Select a card in the three-card row, then drag its right or bottom edge. A live W×H chip follows the corner.

If a max-width was holding the element back, the editor raises the ceiling with it instead of looking broken.

drag sideways

3 · Reorder a row

Drag the middle card left or right. It changes place instead of floating, because its parent is a flex row.

This is the auto-layout instinct from Figma, mapped onto the one thing a web page actually does with children in a row.

state → hover

4 · Design a hover

Select the dark See the collection button, switch state to hover, change its fill. The value is shown at rest so you can judge it.

A resting state is half a design. The report writes it as its own :hover rule rather than merging it into the normal one.

▢ device

5 · Edit the phone without touching desktop

Press device, pick iPhone, change the headline size. Exit the frame: desktop is untouched.

The editor reads the page's real breakpoints and scopes each edit to the band you made it in. Two sizes, two independent values.

▷ use the page

6 · Reach a state, then edit it

Turn on use the page, flip the pricing toggle to Yearly, turn it off again, then restyle the price that appeared.

Anything behind a click used to be uneditable. This is the button that fixed that.

audit

7 · Find the real problems

Open the audit tab, press run checks. Four faults at the bottom of the playground are deliberate. Click ◎ to jump to each one.

Contrast is measured on the colours actually painted, not the ones in the palette, which is where real pages fail.

◇

8 · Write a token, not a number

Select a card, open padding, press ◇ and choose --space-8.

Reporting 24px makes a developer guess. Reporting var(--space-6) keeps the design system intact.

N · ✎ mark

9 · Say what you mean

Select something and press N to pin a note. Or switch to ✎ mark and circle an area freehand, then type the note.

Half of what needs saying about a layout is intent, and intent has no CSS property.

COPY FOR AI

10 · Hand it over

Press the mint button. Paste into Claude, Cursor, or a message to whoever builds the site.

The report names the file, the rule, the media query and the token, and warns when the site's own CSS would beat the change. That is the difference between a screenshot and a patch.

Troubleshooting

When it does not appear.

I clicked the icon and nothing happened

Two usual causes. Either you are on a page Chrome forbids extensions from touching (chrome:// pages, the Web Store, a new tab page), so open a normal website and try again. Or the editor is already loaded and hidden: from 1.9.1 clicking the icon a second time brings a hidden panel back, so update if you are on an older build.

Chrome says the manifest is missing or invalid

You have selected the wrong folder level. The folder you pick must have manifest.json directly inside it. If you picked the zip, or the folder containing the folder, Chrome cannot see the manifest.

The extension vanished after I restarted Chrome

The folder moved or was deleted. Chrome loads an unpacked extension from its path every launch, so keep it somewhere permanent, then use Load unpacked once more.

The console line gives a Content-Security-Policy error

That site blocks outside scripts. Nothing is wrong with the editor and nothing you paste will change it. Use the extension there, which is exempt.

My edits disappeared when the site re-rendered

They should come back within half a second: the editor watches the page and re-applies its changes when a framework replaces the nodes. If they do not, the element it was attached to no longer exists in a recognisable place, and the change list keeps the value so you can re-apply it by hand.

Typing in the site's own form does strange things

Fixed in 1.9.1. Before that, single-letter shortcuts fired while you typed in a page field. Update, and the page's own inputs keep every key.

Can I use it on a site I do not own?

Yes. Everything happens in your browser and nothing is saved to the site. It is the same as opening DevTools and changing a value, with a better set of tools around it.
